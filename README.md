> **Toward scalable ambulatory light dosimetry: sensor-placement bias under

## Aim

Personal light dosimeters are often worn on the chest or wrist even though
light at the eye is the relevant exposure for visual and non-visual responses.
This study quantifies the resulting sensor-placement bias under free-living
conditions using concurrent melanopic equivalent daylight illuminance
measurements from dosimeters worn at the glasses, chest, and wrist.

The analyses address three linked questions:

1. How large is the time-resolved placement error, and how does it vary across
   activities, lighting conditions, photoperiods, and indoor–outdoor contexts?
2. How does placement affect daily and phase-specific personal light-exposure
   metrics?
3. How do participant number and monitoring duration affect the precision of
   population-average bias estimates?

The primary analyses are accompanied by sensitivity analyses that retain
documented non-wear or restrict the metric calculations to valid waking wear.

## Data

The raw multisite MeLiDos field-study data are not duplicated in this
repository. Preparation notebooks retrieve the public source datasets through
the [`melidosData`](https://melidosproject.github.io/melidosData/) R package.
The individual repositories are maintained by the
[MeLiDos project](https://github.com/MeLiDosProject), and their versioned DOIs
are listed in the manuscript's data-availability statement.

Prepared analysis objects are committed under `data/`. They allow the
statistical analyses and manuscript to be inspected or rendered without
re-downloading and preparing the raw 10-second time series. Recreating these
objects from source requires an internet connection. The contextual preparation
notebook also retrieves the MeLiDos timezone definitions from the
`Data_Metadata_Conventions` repository.

## Reproducibility guide

### 1. Install the prerequisites

The archived computational environment uses:

- R 4.5.0;
- Quarto 1.9.x (the project was checked with Quarto 1.9.37);
- Git; and
- an internet connection for package restoration and source-data retrieval.

A Chromium-based browser such as Google Chrome or Chromium is needed when
regenerating PNG tables through `gt` and `webshot2`. Cairo support in R is used
for several PDF figures.

### 2. Obtain the repository

Clone the current repository:

```bash
git clone https://github.com/tscnlab/ZaunerDeVriesEtAl_JExpoSciEnvironEpidemiol_2026.git
cd ZaunerDeVriesEtAl_JExpoSciEnvironEpidemiol_2026
```

For an exact reproduction of the current archived release, check out its tag:

```bash
git checkout v0.9.9
```

Alternatively, download the corresponding source archive from
[Zenodo](https://doi.org/10.5281/zenodo.21533915).

### 3. Restore the R environment

Run the following command from the repository root:

```bash
R -q -e 'renv::restore(prompt = FALSE)'
```

The project-level `.Rprofile` activates `renv` automatically. The lockfile pins
the package versions and the exact Git commit used for `melidosData`.

Confirm that the library is synchronized and that Quarto is available:

```bash
R -q -e 'renv::status()'
quarto --version
```

### 4. Choose the reproduction level

#### Fast render from committed results

To rebuild the manuscript website using the committed prepared data and frozen
notebook computations:

```bash
quarto render
```

The project uses `freeze: auto`, so unchanged notebooks reuse `_freeze/`.
This is the quickest way to build `docs/index.html`, but it does not test the
complete data-preparation and analysis pipeline.

#### Full re-execution

For a complete reproduction, execute the notebooks in the dependency order
below. Run every command from the repository root. These commands regenerate
tracked files under `data/` and `output/`.

First, prepare and analyse the measurement-level contextual data:

```bash
quarto render notebooks/SWV_context_preparation.qmd --execute
quarto render notebooks/SWV_context_comparison.qmd --execute
```

Next, prepare and analyse the primary outcome-level metrics:

```bash
quarto render notebooks/JZ_metric_preparation.qmd --execute
quarto render notebooks/JZ_metric_comparison.qmd --execute
```

Run the sensitivity analysis that retains documented non-wear:

```bash
quarto render notebooks/JZ_metric_preparation_nonwear.qmd --execute
quarto render notebooks/JZ_metric_comparison_nonwear.qmd --execute
```

Run the wake-only sensitivity analysis. Its preparation step depends on the
primary prepared metrics created above:

```bash
quarto render notebooks/JZ_metric_preparation_wake_only.qmd --execute
quarto render notebooks/JZ_metric_comparison_wake_only.qmd --execute
```

Finally, reproduce the sample-size stability analysis:

```bash
quarto render notebooks/JZ_error_stabilisation.qmd --execute
```

The production stability analysis uses 10,000 bootstrap draws and is the most
computationally intensive step. A short execution test can be run with:

```bash
quarto render notebooks/JZ_error_stabilisation.qmd --execute -P draws:100
```

The short test overwrites the stability outputs with explicitly labelled
non-production results. Rerun the default 10,000-draw command before building
the final manuscript.

### 5. Assemble the manuscript site

After all analysis notebooks have completed, render the full project:

```bash
quarto render
```

The main local output is `docs/index.html`. Each analysis notebook is also
rendered into `docs/notebooks/` and linked from the manuscript site.

For a local live preview:

```bash
quarto preview
```

Stop the preview server with `Ctrl+C`.

### 6. Check the regenerated results

Confirm that the manuscript and expected result directories exist:

```bash
test -f docs/index.html
test -d output/figures
test -d output/tables
git status --short
```

Changes under `data/`, `output/`, `_freeze/`, or `docs/` show which generated
artifacts differ from the archived version. Small rendering differences can
arise across operating systems because of fonts, browser versions, or graphics
devices; substantive numerical results should remain unchanged.
